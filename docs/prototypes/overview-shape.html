O-07 三个层级分别能说明什么、不能说明什么 乙 · 它怎么跑 Source: §3, §4, §5 折叠
全文的地基。原文用三段散文分别讲三级"能说明 / 不能说明"，这里并成一张三行对照表 —— 这是最典型的"散文换表格"：内容一条不少，但一眼能扫完。
层级能说明不能说明
Receipt ✓ 收到了某个 Proposal / 冻结上下文或传输结果；传输层或接收层记录了到达事实； 后续系统有机会继续做授权、版本和语义关联检查 ✗ 已通过合法性校验；属于当前生成请求；已经冻结；当前生成一定可以使用它； 生成器实际读过或使用了其中的教学语义；最终 outline / scene 已经对齐
Availability ✓ 来自受信任服务端路径（非浏览器伪造）；请求 / session / Frozen Context lineage 一致； schema、revision、digest、引用范围、授权检查通过；是同一个冻结上下文； 生命周期内仍有效；生成阶段具备服务端访问能力 ✗ 生成器已经真正使用了上下文。它只说明："如果生成器需要，它现在可以合法、稳定地使用这份上下文。"
Consumption ✓ 本次 outline generation 实际使用了冻结上下文中的教学语义，并将其作为课程设计输入， 而不是仅仅收到、保存或附加了上下文 ✗ 不能由"收到 / 保存 / 附加 / Prompt 变长 / 生成成功"推出 —— 见 O-10
O-10 HOW DO WE KNOW？怎样证明某个状态真的发生了 丙 · 怎么算发生了 Source: §3, §4, §5, §12 折叠
这一节不是"再定义三个名词"，而是规定怎样举证。 它同时装下两个最容易被误解的判断：成功返回不等于发生了消费；生成失败也不等于没消费。

Evidence

这些都不能单独证明 Consumption

  • context stored上下文被保存了
  • context field exists生成请求参数里出现 context 字段
  • prompt contains contextPrompt 里包含了上下文文本

最低证据方向（注意：不是已确定的证据结构）

Frozen Context → Projection → Generation Attempt → Consumption Evidence

原文只确定"最低证据应以 generation-level 为主"，没有决定 evidence 的具体结构 —— 这仍是未决项 Q-002。

两个反直觉判断

  • 生成成功 ≠ 发生了 Consumption 如果 projection 没有成为真实生成输入，只能算 Receipt 或 Availability
  • 生成失败 ≠ 没发生 Consumption 只要某次实际 Attempt 已合法使用了 generation-facing projection
O-11 Consumption 不要求什么 / 可能出现的不一致状态 丙 · 怎么算发生了 Source: §5, §8 折叠
这里混了两件不同性质的事，所以拆成两个形状：左边是"不要求"，右边是"状态关系"。

(a) What Consumption does NOT require

不要求盲目服从
  • 某项 Recommended 被纳入设计考虑后最终没采用，仍可能满足 Consumption 会在 Output Alignment 记为 Not adopted，但不得伪称已经采用
  • 完全没有把某项 guidance 纳入生成设计考虑 这反映 Consumption 不充分，不能用 Alignment 的最终采用状态解释过去
不要求最终输出明显不同
  • 冻结上下文判断学习者与课程同通用设计一致时，输出可以接近默认 outline
  • 为"证明个性化"而强行制造结构差异 反而可能破坏合理的课程设计

(b) Possible mismatch states

Consumption = yes / Alignment = no
上下文确实参与了生成，但结果没有满足相关 Required 或没有充分体现目标、范围和教学设计
Consumption = no / Alignment = apparently yes
结果可能来自默认模板、通用教学模式或偶然相似；不能把它归因于 DeepTutor

只有两个目标共同成立，才支持"本次课程在可追踪意义上消费并体现了 DeepTutor 的课前教学语义"。
